* Keyboard/tracking focus stuck (typing dies, only workspace-switch restores)
  - ROOT CAUSE (hypr side): =general.no_focus_fallback = true= (general.lua:16).
    When the focused window closes/floats (`SUPER+V`)/moves workspace (`SUPER+O`),
    Hyprland left NO window focused instead of falling back — keyboard went nowhere
    until a workspace re-activation refocused something. Matched the symptom
    "have to change focus back and forth to make it focus windows".
  - FIX: =no_focus_fallback = false= (reloaded live via =hyprctl reload=, verified
    =general:no_focus_fallback = false=).
  - STILL OPEN if it recurs: =input:follow_mouse=1= + =float_switch_override_focus=2=
    (commonVariables.lua:38 TODO) and the WlSessionLock lock integration. Next lever if
    needed: =input:follow_mouse = 2=.
  - Verified during monitoring: no transient exclusive/grab layer appears while typing;
    the only always-mapped top-level surface is the 1×1 caffeine idle-inhibitor window
    (input-transparent, keyboardFocus none — not the cause).
